```markdown
# Проектный Менеджер - Инструменты Контроля Соответствия

**Project Manager Compliance Tools**

## Концепция

### Разделение Ответственности

**Проектный Менеджер** = Контроль соответствия + Тесты (КАК должно быть)
- Знает ожидаемую конфигурацию
- Проверяет соответствие требованиям
- Обнаруживает отклонения
- Выдает рекомендации

**Центральный Мозг** = Стратегия + Ресурсы (ЧТО есть)
- Получает фактическое состояние
- Принимает стратегические решения
- Распределяет ресурсы
- Не занимается проверками

## Приоритеты Проверок

Проверки выполняются в строгом порядке приоритетов:

### ПРИОРИТЕТ 1: Конфликты Портов ⚠️ **КРИТИЧНО**
**Файл**: `compliance-checks/priority_1_port_conflicts.py`

**Почему первое**:
- Конфликты портов блокируют запуск сервисов
- Должно быть проверено ДО всех других проверок
- Если есть конфликты - остальные проверки бессмысленны

**Что проверяет**:
- ✅ Нет ли нескольких сервисов на одном порту
- ✅ Нет ли неизвестных процессов на зарезервированных портах
- ✅ Все ли критичные порты свободны/заняты правильными сервисами

**Результат для Центрального Мозга**:
```json
{
  "ports": {
    "total_ports_listening": 15,
    "ports": [
      {"port": 8011, "process": "planning-service", "is_expected": true},
      {"port": 8023, "process": "plans-service", "is_expected": true}
    ]
  }
}
```

### ПРИОРИТЕТ 2: Интеграция с Метриками
**Файл**: `compliance-checks/priority_2_metrics_integration.py`

**Почему второе**:
- После портов проверяем подключение к мониторингу
- Без метрик невозможно контролировать производительность
- Grafana + Prometheus - основа наблюдаемости

**Что проверяет**:
- ✅ Prometheus доступен и собирает метрики
- ✅ Grafana доступен
- ✅ Каждый сервис экспортирует метрики (/metrics endpoint)
- ✅ Каждый сервис зарегистрирован в Prometheus targets
- ✅ Prometheus активно scraping метрики
- ⚠️ (опционально) Есть ли dashboard в Grafana

**Результат для Центрального Мозга**:
```json
{
  "metrics": {
    "prometheus_available": true,
    "grafana_available": true,
    "services_with_metrics": 18,
    "total_services": 24
  }
}
```

### ПРИОРИТЕТ 3: Подключение к Базам Данных
**Файл**: `compliance-checks/priority_3_database_connections.py`

**Почему третье**:
- После портов и метрик проверяем БД
- Без БД сервисы не могут хранить данные
- Проверяем схемы и миграции

**Что проверяет**:
- ✅ PostgreSQL доступен
- ✅ Redis доступен
- ✅ Каждый сервис подключен к своей БД
- ✅ Схемы БД существуют
- ✅ Обязательные таблицы созданы
- ⚠️ (опционально) Миграции применены

**Результат для Центрального Мозга**:
```json
{
  "databases": {
    "postgres_available": true,
    "redis_available": true,
    "services_connected": 20,
    "total_services": 24
  }
}
```

### ПРИОРИТЕТ 4: Регистрация KPI (TODO)

### ПРИОРИТЕТ 5: Публикация Событий в EventBus (TODO)

- ✅ Сервис подписан на релевантные события
- ✅ Heartbeat отправляется регулярно (каждые 30с)

- ✅ Сервис управляется оркестратором (docker-compose/k8s)
- ✅ Оркестратор знает о статусе сервиса
- ✅ Есть health checks
- ✅ Есть restart policy

## Интеграция с Центральным Мозгом

Проектный Менеджер предоставляет **фактическое состояние** Центральному Мозгу:

```python
from infrastructure.tools.project_manager import ComplianceCheckRunner

runner = ComplianceCheckRunner()
runner.run_all_checks()

# Получить фактическое состояние для Центрального Мозга
state = runner.export_state_for_central_brain()

# state содержит ТОЛЬКО факты, БЕЗ требований:
{
  "timestamp": "2025-10-09T14:30:00",
  "ports": {...},      # Какие порты слушают
  "metrics": {...},    # Prometheus/Grafana доступны
  "databases": {...}   # PostgreSQL/Redis доступны
}

# Центральный Мозг использует это для принятия решений:
# - Достаточно ли ресурсов?
# - Можно ли запустить новый сервис?
# - Нужно ли масштабирование?
```
