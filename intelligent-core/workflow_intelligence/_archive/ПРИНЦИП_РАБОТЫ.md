## 🎯 ЧТО ЭТО?

**Workflow Intelligence** - это "мозг" платформы, который:
1. **Управляет рабочими процессами** (BIA, Risk Assessment, Planning)
2. **Учится на опыте** (собирает кейсы, анализирует паттерны)
3. **Дает рекомендации** (на основе ML и 347+ кейсов)
4. **Обеспечивает надежность** (через Temporal Cloud)

**Простая аналогия**: Это как "автопилот для BCM процессов" - вы говорите "начать BIA", а он ведет вас шаг за шагом, подсказывает на основе опыта других компаний, и следит чтобы ничего не потерялось.

**Что происходит (Валидация!)**:

```python
# 1. State Machine проверяет условия перехода
transition = state_machine.get_transition(
    from_state="IDENTIFY_PROCESSES",
    to_state="ANALYZE_DEPENDENCIES"
)

# 2. Проверка condition (условие)
condition_check = transition.condition(state_machine.current_state.data)
# condition: len(data.get('processes', [])) >= 3
# → У нас 3 процесса → TRUE ✅

# 3. Проверка required_data (обязательные поля)
required_data_check = all(
    field in state_machine.current_state.data
    for field in transition.required_data
)
# required_data: ['processes']
# → Есть 'processes' → TRUE ✅

# 4. Выполнение validators (функции валидации)
def _validate_processes(data):
    processes = data.get('processes', [])

    # Проверка 1: Минимум 3 процесса
    if len(processes) < 3:
        raise ValidationError("At least 3 processes required")

    # Проверка 2: У каждого процесса есть name
    for p in processes:
        if not p.get('name'):
            raise ValidationError("Process name is required")

    # Проверка 3: У каждого процесса есть criticality
    for p in processes:
        if p.get('criticality') not in ['HIGH', 'MEDIUM', 'LOW']:
            raise ValidationError("Invalid criticality level")

    return True

validation_result = _validate_processes(state_machine.current_state.data)
# → Все проверки прошли → TRUE ✅

# 5. Выполнение on_exit hook (выход из текущего состояния)
def _on_exit_identify_processes(workflow_data):
    # Публикует событие
    publish_event("bia.stage.completed", {
        "stage": "IDENTIFY_PROCESSES",
        "bia_id": "bia_456",
        "processes_count": len(workflow_data['processes'])
    })

    # Добавляет метрику
    metrics.increment("bia.processes.identified", 3)

# 6. Создание snapshot для rollback
snapshot = StateSnapshot(
    state=state_machine.current_state.copy(),
    timestamp=datetime.utcnow(),
    transition_id="transition_789"
)
state_machine.snapshots.append(snapshot)

# 7. Переход в новое состояние
state_machine.current_state = WorkflowState(
    name="ANALYZE_DEPENDENCIES",
    entered_at=datetime.utcnow()
)

# 8. Выполнение on_enter hook (вход в новое состояние)
def _on_enter_analyze_dependencies(workflow_data):
    # Получает рекомендации от ML
    ml_recommendations = ml_engine.predict_dependencies(
        processes=workflow_data['processes'],
        industry="healthcare"
    )
    # → "Patient Care зависит от Medical Records (90% probability)"

    return {
        "ml_recommendations": ml_recommendations
    }

# 9. Сохранение в Temporal
temporal_workflow.transition_to("ANALYZE_DEPENDENCIES")
```

## 🎓 CASE LIBRARY (Как работает обучение)

### **Что происходит когда BIA завершается**

```python
# Когда пользователь доходит до COMPLETED:

# 1. Собирается полный кейс
case_data = {
    "industry": "healthcare",
    "size": "medium",
    "location": "US",
    "processes": [
        {
            "name": "Patient Care",
            "criticality": "HIGH",
            "rto_hours": 4,
            "mtpd_hours": 8
        },
        # ...
    ],
    "total_duration_days": 7,
    "completion_rate": 100,
    "outcome": "success"
}

# 2. Анонимизация (k-anonymity)
anonymized_case = anonymizer.anonymize(case_data)
# → Удаляет: company name, contact info, specific locations
# → Сохраняет: industry, size, processes (generic names), metrics

# 3. Проверка k-anonymity (минимум 5 похожих)
similar_count = case_library.count_similar(anonymized_case)
# → Если < 5 → НЕ добавляем (privacy risk)
# → Если >= 5 → Добавляем

if similar_count >= 5:
    # 4. Добавление в Case Library (PostgreSQL)
    case_id = case_library.add_case(anonymized_case)

    # 5. Добавление в Vector DB (Qdrant) для similarity search
    case_vector = vectorizer.encode(anonymized_case)
    qdrant_client.upsert(
        collection_name="bia_cases",
        points=[{
            "id": case_id,
            "vector": case_vector,
            "payload": anonymized_case
        }]
    )

    # 6. Публикация события
    publish_event("case_library.case_added", {
        "case_id": case_id,
        "module": "bia",
        "source": "community"
    })

    # 7. Запуск ML переобучения (async)
    ml_engine.retrain_model(
        new_cases=[case_id]
    )
```

## ⚡ TEMPORAL WORKFLOWS (Как обеспечивается надежность)

### **Проблема**: Что если сервер упал во время BIA?

**БЕЗ Temporal**:
```
Пользователь заполнил 3 из 5 шагов BIA
→ Сервер перезагрузился
→ Состояние потеряно
→ Пользователь начинает заново ❌
```

**С Temporal**:
```python
# 1. Каждый переход сохраняется в Temporal Cloud
@temporal_workflow
async def bia_workflow(bia_id: str, org_context: dict):
    # Temporal автоматически сохраняет состояние

    # Шаг 1
    await activity_identify_processes()
    # → Сохранено в Temporal

    # Шаг 2
    await activity_analyze_dependencies()
    # → Сохранено в Temporal

    # Если сервер упадет здесь → Temporal ВОССТАНОВИТ
    # и продолжит с Шага 2!

    # Шаг 3
    await activity_assess_impact()

    return {"status": "completed"}

# 2. При перезапуске сервера
# Temporal автоматически:
# - Восстанавливает все активные workflows
# - Продолжает выполнение с последнего сохраненного состояния
# - Retry при ошибках (exponential backoff)

# 3. Пользователь просто продолжает работу
# Он даже не замечает что был перезапуск!
```

### **Temporal Features**:

1. **Durable Execution**: Состояние НЕ теряется
2. **Automatic Retry**: Если API call failed → retry (configurable)
3. **Timeout Support**: Если workflow застрял → timeout
4. **Event History**: Полная история всех событий
5. **Debugging**: Можно посмотреть что пошло не так

### **Checkpoint Manager**

```python
# Checkpoints - это обязательные проверки:

@checkpoint("iso_22301_clause_8_2")
def validate_bia_completeness(workflow_data):
    """ISO 22301 Clause 8.2: BIA must be complete"""

    # Проверка 1: Все критические процессы идентифицированы
    if not workflow_data.get('processes'):
        return CheckpointResult(
            passed=False,
            message="No processes identified (ISO 22301 non-compliant)"
        )

    # Проверка 2: RTO определены
    for process in workflow_data['processes']:
        if not process.get('rto_hours'):
            return CheckpointResult(
                passed=False,
                message=f"Process {process['name']} missing RTO"
            )

    return CheckpointResult(passed=True)

# Если checkpoint fails → workflow БЛОКИРУЕТСЯ
# Нельзя перейти к следующему шагу пока не исправлено
```

            "user_prompt": f"Context: {ai_context}\n\nRecommend RTO",
            "temperature": 0.7
        }
    )

    ai_recommendation = response.json()['response']

    return ai_recommendation

## 🎯 SUMMARY (КЛЮЧЕВЫЕ МОМЕНТЫ)

### **Что делает Workflow Intelligence?**

1. **Управляет пошаговыми процессами** (State Machine)
   - BIA: 6 этапов (Identify → Analyze → Assess → Determine → Review → Complete)
   - Нельзя пропустить шаги
   - Валидация на каждом шаге

2. **Обеспечивает надежность** (Temporal Cloud)
   - Состояние НЕ теряется при перезапуске
   - Автоматический retry
   - Timeout support

3. **Учится на опыте** (Case Library + ML)
   - 347+ анонимизированных кейсов
   - Vector search похожих компаний
   - ML-powered рекомендации (87% accuracy)

4. **Следит за качеством** (Governance)
   - ISO 22301 checkpoints
   - Обязательные поля
   - Валидаторы

5. **Интегрируется с платформой** (EventBus)
   - Координирует с BIA/Risk/Planning services
   - AI-powered рекомендации через AI Foundation
   - Делится кейсами с Collective Intelligence

### **Когда его использовать?**

- ✅ **Любой многошаговый процесс** (BIA, Risk Assessment, Planning)
- ✅ **Нужна надежность** (нельзя потерять данные при сбое)
- ✅ **Нужны рекомендации** (на основе ML и кейсов)
- ✅ **Нужно ISO compliance** (checkpoints и валидация)

### **Почему это важно?**

Без Workflow Intelligence:
```
❌ Пользователь может пропустить важные шаги
❌ При сбое сервера → все данные потеряны
❌ Нет рекомендаций → пользователь не знает что писать
❌ Нет валидации → можно создать некорректный BIA
```

С Workflow Intelligence:
```
✅ Шаг за шагом ведет пользователя
✅ Состояние сохраняется в Temporal Cloud
✅ ML рекомендации на основе 347+ кейсов
✅ ISO 22301 compliance автоматически
```
