## ❌ `/bcm_ai/` - ДУБЛИКАТ (создан по ошибке)

**Что там**: Попытка создать единую BCM AI систему, НО дублирует существующую инфраструктуру

**Структура**:
```
bcm_ai/
├── specialists/          # Базовый класс для диалогов
│   └── base_specialist.py
│   └── risk_specialist/  # Specialist для рисков
│
├── engines/             # Бизнес-логика
│   └── risk_engine/
│       ├── risk_engine.py
│       └── risk_tools.py
│
├── analyzers/           # LLM анализаторы
│   └── base_analyzer.py
│   └── risk_analyzer.py
│
└── core/                # Ядро (ДУБЛИКАТЫ!)
    ├── llm/llm_router.py      # ✅ ЭТО ХОРОШО (можно оставить)
    ├── pdca/pdca_engine.py    # ❌ ДУБЛИКАТ workflow_intelligence
    └── case_library/repository.py  # ❌ ДУБЛИКАТ workflow_intelligence
```

**Проблемы**:
- ❌ PDCA Engine - упрощенная версия, **уже есть** в `/workflow_intelligence/core/state_machine.py`
- ❌ Case Library - базовая версия, **уже есть** в `/workflow_intelligence/core/case_library/`
- ❌ RAG интеграция - заглушки, **уже есть** в `/ai_experts/rag/`

**Что хорошего**:
- ✅ `llm_router.py` - production-ready LLM роутер (Anthropic + OpenAI fallback)
- ✅ Базовые классы неплохие

**Решение**:
1. **Переместить в архив**: `/_archive/bcm_ai_OLD/`
2. **Извлечь полезное**: `llm_router.py` → использовать в новой архитектуре

## ✅ `/bcm_offices/` - ПРАВИЛЬНАЯ АРХИТЕКТУРА (новая)

**Что там**: Модульные BCM офисы, интегрированные с существующей инфраструктурой

**Структура**:
```
bcm_offices/
└── risk/                    # Первый готовый офис
    ├── workflow/
    │   └── risk_workflow.py      # Extends workflow_intelligence.StateMachine ✅
    │
    ├── ai/
    │   ├── expert.py             # Бизнес-логика + интеграция
    │   ├── specialist.py         # Диалог (extends ExpertAgent) ✅
    │   └── organ.py              # LLM (мигрирован из ai_organs) ✅
    │
    ├── tools/
    │   └── risk_tools.py         # DB операции
    │
    ├── services/
    │   └── risk_service.py       # Главный оркестратор
    │
    ├── __init__.py
    └── README.md                 # Полная документация
```

**Почему это правильно**:
- ✅ **Extends** StateMachine из workflow_intelligence (не дублирует)
- ✅ **Uses** AIContextBuilder из workflow_intelligence (не дублирует)
- ✅ **Uses** CaseLibraryRepository из workflow_intelligence (не дублирует)
- ✅ **Migrates** RiskAdvisor из ai_organs (переиспользует)
- ✅ **Follows** ExpertAgent pattern из ai_experts (переиспользует)
- ✅ **Event-driven** интеграция через EventBus
- ✅ **Модульная** структура - каждый офис = отдельный сервис

**Использование**:
```python
from bcm_offices.risk import RiskService

service = RiskService(db, llm, event_bus, org_context)
response = await service.chat("Identify risks...", {...})
```

**Статус**: ✅ Risk Office готов, можно использовать как шаблон для 9 остальных офисов

## ✅ `/ai_platform/` - РОУТЕР ЗАПРОСОВ (высокоуровневый)

**Что там**: Система маршрутизации запросов - 3-уровневая иерархия менеджеров

**Структура**:
```
ai_platform/
├── chief/
│   └── chief_executive.py       # Level 0: Главный координатор
│                                 # Анализирует intent → роутит к менеджерам
│
├── managers/                     # Level 1: TOP менеджеры по сегментам
│   ├── domain_manager.py         # BCM сегмент (10 экспертов: BIA, Risk, Planning...)
│   ├── platform_manager.py       # Platform сегмент (5 экспертов: Workflow, MIO, DevOps...)
│   └── governance_manager.py     # Governance сегмент (Compliance, Audit...)
│
└── shared/base/                  # Базовые классы для роутинга
    ├── base_manager.py           # Базовый менеджер
    ├── base_expert.py            # Базовый эксперт
    ├── base_organ.py             # Базовый орган
    └── base_tool.py              # Базовый инструмент
```

**Как работает**:

### Level 0: Chief Executive AI
```python
# Главный координатор - ТОЧКА ВХОДА для всех запросов
chief = ChiefExecutiveAI(
    governance_manager=GovernanceManager(),
    platform_manager=PlatformManager(),
    domain_manager=DomainManager(),  # BCM Manager
    llm_client=llm
)

result = await chief.handle_request(
    user_query="Calculate BIA for payment processing",
    context={'org_id': 'org_123', ...}
)
```

**Функции ChiefExecutiveAI**:
1. **Анализирует intent** (keyword-based ИЛИ LLM-based):
   - Ключевые слова по сегментам
   - Fallback на LLM если не нашли keywords

2. **Определяет сегмент**:
   - **GOVERNANCE**: compliance, audit, policy, ISO, certification...
   - **PLATFORM**: workflow, deployment, performance, MIO, architecture...
   - **DOMAIN** (BCM): BIA, risk, recovery, incident, continuity...

3. **Роутит к TOP менеджеру** нужного сегмента

4. **Трекает метрики**:
   - Routing accuracy
   - Average response time
   - Total requests

### Level 1: TOP Managers

**DomainManager** (BCM Manager):
```python
# Координирует 10 BCM экспертов
```

**PlatformManager**:

**GovernanceManager**:
```python

```

### Level 2: Experts
(Делегируются из менеджеров - BIA Specialist, Risk Analyst и т.д.)

**Роль в архитектуре**:
- ✅ **Routing Layer** - НЕ дубликат!
- ✅ **Intent Classification** - определяет куда направить запрос
- ✅ **Manager Hierarchy** - управляет экспертами через менеджеров

**Отличие от других базовых классов**:
- `ai_platform/shared/base/base_manager.py` - для РОУТИНГА и управления
- `/ai_experts/base/expert_agent.py` - для ЭКСПЕРТОВ (domain logic)
- `/ai-orchestration/muscles/ai_organs/base_organ.py` - для LLM ОРГАНОВ

Разные абстракции для разных целей!


```
     ↓
```

```
     ↓
```

```
     ↓
```
