Model 2: Anomaly Detector

Z-Score + Statistical Analysis

What It Detects:

  • Duration Anomalies: Tasks taking unusually long (Z > 2)
  • Stagnation: No progress for >14 days
  • Inactivity: No user activity for >7 days
  • Activity Bursts: Sudden spikes (>20 actions/day)
  • Data Quality Issues: Missing or inconsistent data

Why Z-Score?

  • Statistical Rigor: Identifies outliers mathematically
  • Threshold: Z > 2 = 95% confidence it's anomalous
  • Real-time: Detects issues as they happen
  • Interpretable: Clear explanation for each alert
# Anomaly Detection Algorithm from scipy import stats import numpy as np def detect_anomalies(duration_hours, historical_durations): # Calculate Z-score mean = np.mean(historical_durations) std = np.std(historical_durations) z_score = (duration_hours - mean) / std # Anomaly if Z > 2 (95% confidence) if z_score > 2: return { "anomaly": True, "z_score": z_score, "severity": "high" if z_score > 3 else "medium", "message": f"Duration {duration_hours}h is {z_score:.1f} std devs above normal" } return {"anomaly": False} # Example: BIA stage taking 42 hours (historical avg: 18h, std: 8h) result = detect_anomalies(42, [15, 18, 20, 16, 22, 19]) # → Z-score: 3.0 → High severity anomaly detected!

8 ML Features: What Powers Predictions

Every prediction uses these 8 contextual features extracted from your organization

Feature 1

org_size

Type: Categorical (small / medium / large)

Why Important: Larger organizations typically take longer for BCM implementation due to complexity, more stakeholders, and more processes to analyze. Small orgs move faster but may lack resources.

Example: Healthcare clinic (50 staff) → small | Regional hospital (500 staff) → medium | Hospital system (5000+ staff) → large
Feature 2

org_maturity

Type: Ordinal (1-5 scale)

Why Important: Organizations with higher BCM maturity complete stages faster - they have existing processes, trained staff, and institutional knowledge. Level 1 orgs need more guidance.

Scale: 1 = No BCM experience | 2 = Basic awareness | 3 = Developing | 4 = Established | 5 = Optimizing
Feature 3

industry

Type: Categorical (healthcare / finance / manufacturing / etc.)

Why Important: Different industries have different regulatory requirements, risk profiles, and BCM complexities. Healthcare has patient safety considerations, finance has data protection needs.

Supported: Healthcare, Finance, Manufacturing, Education, Government, Retail, Technology, Energy
Feature 4

stage_index

Type: Numeric (current position in workflow)

Why Important: Early stages (BIA, Risk Assessment) tend to take longer as they're foundational. Later stages build on previous work and move faster. This feature captures workflow position.

Example: BIA module has 7 stages → Currently at stage 3 → stage_index = 3
Feature 5

total_stages

Type: Numeric (workflow length)

Why Important: Workflows with more stages are inherently more complex. BIA might have 7 stages, while Plan Creation has 12. More stages = longer completion time and higher stuck probability.

Range: Typical BCM workflows have 5-15 stages depending on module complexity
Feature 6

complexity

Type: Ordinal (1-5 scale)

Why Important: User-assessed complexity rating. A simple Risk Assessment (complexity=2) will complete faster than a comprehensive enterprise-wide BIA (complexity=5). Subjective but predictive.

Scale: 1 = Very simple | 2 = Simple | 3 = Moderate | 4 = Complex | 5 = Very complex
Feature 7

ai_usage_count

Type: Numeric (number of AI interactions)

Why Important: Organizations that leverage AI assistance more frequently tend to move faster and get unstuck quicker. This captures AI adoption level and correlates with completion speed.

Example: Org using 14 AI specialists heavily → ai_usage_count = 47 → Predicts faster completion
Feature 8

challenges_count

Type: Numeric (issues encountered)

Why Important: Number of roadblocks, challenges, or issues reported during implementation. Higher challenge count correlates with longer duration and higher stuck probability. Early warning signal.

Threshold: challenges_count > 5 → High risk of getting stuck, expert help strongly recommended

How Features Combine to Make Predictions

ML models analyze all 8 features simultaneously to find patterns. For example, a large healthcare organization (feature 1 + 3) with low maturity (feature 2) at a complex stage (feature 6) with few AI interactions (feature 7) → High stuck probability prediction.

# Feature Vector Example features = { "org_size": "medium", # 500 employees "org_maturity": 2, # Developing "industry": "healthcare", # Sector "stage_index": 3, # Current stage "total_stages": 7, # Workflow length "complexity": 4, # High complexity "ai_usage_count": 12, # Moderate AI adoption "challenges_count": 3 # Some issues } # ML model predicts: prediction = model.predict(features) # → duration: 18h, stuck_prob: 0.35, expert_help: True

Why Predictive Intelligence is Revolutionary

The paradigm shift from reactive to proactive BCM

Traditional BCM Approach
