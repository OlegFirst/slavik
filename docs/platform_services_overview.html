Platform Services Responsibilities:

  • Business Logic: Implement BCM workflows (BIA, Risk, Plans, etc.)
  • Data Persistence: Store and retrieve domain data from PostgreSQL
  • Event Choreography: Publish/subscribe to business events via EventBus
  • ISO 22301 Compliance: Enforce standard requirements across all modules
  • API Exposure: Provide RESTful APIs for applications and AI services

Core BCM Services

BIA Service

Business Impact Analysis

:8004

Identifies critical business functions, assesses impact of disruptions, and calculates recovery time objectives (RTO) and recovery point objectives (RPO).

Key Capabilities:

  • Critical function identification
  • Impact assessment (financial, operational, reputational)
  • RTO/RPO calculation
  • Dependency mapping (internal/external)
  • Resource requirement analysis
  • BIA reporting & visualization

ISO 22301 Mapping:

  • Clause 8.2.2: Business impact analysis
  • Clause 8.2.3: Risk assessment integration
  • Clause 8.4.3: Resource requirements

Integration:

  • Feeds into Risk Assessment (:8005)
  • Feeds into Plans Management (:8006)
  • Uses Workflow Intelligence (:8030)

Example API:

Risk Assessment

Threat Identification & Scoring

:8005

Identifies threats and vulnerabilities, assesses likelihood and impact, calculates risk scores, and develops mitigation strategies.

Key Capabilities:

  • Threat identification (natural, technical, human)
  • Vulnerability assessment
  • Risk scoring (likelihood × impact)
  • Risk matrix generation
  • Mitigation strategy development
  • Risk register management

ISO 22301 Mapping:

  • Clause 8.2.3: Risk assessment
  • Clause 6.1: Actions to address risks
  • Clause 8.3: Business continuity strategies

Integration:

  • Uses BIA results (:8004)
  • Feeds into Plans Management (:8006)
  • Uses Predictive Service (:8036)

Risk Scoring Formula:

Risk Score = Likelihood (1-5) × Impact (1-5) = 1-25

High Risk: ≥15 | Medium Risk: 8-14 | Low Risk: ≤7

FastAPI Framework

  • Async/Await: High-performance async I/O
  • Pydantic: Data validation & serialization
  • OpenAPI: Auto-generated API docs
  • Type Hints: Static type checking

PostgreSQL Storage

  • 29 Schemas: Modular data organization
  • RLS: Row-Level Security (multi-tenancy)
  • JSONB: Flexible document storage
  • Indexes: Optimized query performance

EventBus Integration

  • Pub/Sub: Event-driven choreography
  • Redis Streams: Durable message queue
  • Type-Safe: Structured event definitions
  • Async: Non-blocking event handling

Example: Cross-Service Workflow

How services work together: BIA → Risk → Plans → Response

Scenario: New Hospital Emergency Department Assessment

sequenceDiagram participant User as BCM Manager participant BIA as BIA :8004 participant Risk as Risk :8005 participant Plans as Plans :8006 participant Response as Response :8007 participant EB as EventBus :8003 participant AI as AI Orchestrator :8002 User->>BIA: Create BIA Assessment
(Emergency Department) BIA->>BIA: Calculate RTO=4h, RPO=1h BIA->>EB: Publish bia.assessment.created BIA-->>User: Assessment created EB->>Risk: Receive bia.assessment.created Risk->>Risk: Auto-create risk assessment Risk->>Risk: Identify threats (power outage,
equipment failure) Risk->>EB: Publish risk.assessment.created Risk-->>User: Risks identified EB->>Plans: Receive risk.assessment.created Plans->>AI: Request plan generation AI->>Plans: Generated BCP template Plans->>Plans: Create BCP v1.0 Plans->>EB: Publish plan.created Plans-->>User: BCP ready for review User->>Plans: Approve & activate BCP Plans->>Response: Register active plan Response->>EB: Publish plan.activated Response-->>User: Plan activated, team notified

Key Takeaways:

  • Event-Driven: Services communicate via EventBus, not direct calls
  • Loosely Coupled: Each service operates independently
  • AI-Assisted: AI Orchestrator helps generate plans
  • Automated Workflow: Minimal manual intervention required
