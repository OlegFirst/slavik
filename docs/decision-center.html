What is the Decision Center?

The AI Orchestrator is the central decision-making engine that coordinates all autonomous actions across the platform. It aggregates context, assesses priority, selects strategies, validates safety, and executes or delegates decisions.

Core Responsibilities

1. Aggregate Context

Collect and synthesize information from all platform sources: platform state, workflows, events, similar situations, governance rules

2. Assess Priority

Determine urgency level (Low, Normal, High, Critical) based on impact, time sensitivity, and risk factors

3. Select Strategy

Choose best action from memory of past decisions or generate new strategy using AI and evidence-based reasoning

4. Validate Safety

Check against constitution rules, detect loops, prevent hallucinations, ensure compliance with governance constraints

5. Execute/Delegate

Either auto-resolve, delegate to specialists, escalate to humans, wait-and-monitor, or emergency stop

6. Learn & Evolve

Store outcomes in 4-layer memory, run evolution cycles, improve strategies based on real-world effectiveness

Component Deep Dives

1. Context Aggregator

Purpose: Collect comprehensive context from all platform sources

Data Sources:

  • Database: workflows, processes, risks, plans
  • Cache (Redis): recent events, platform state
  • Memory: similar historical situations
  • Governance: applicable rules and constraints
  • Predictive: AI forecasts for situation
  • External: industry trends (stub), regulatory changes (stub)

Output: FullContext

  "workflows": [...],
  "recent_events": [...],
  "similar_situations": [...],
  "industry_trends": [...],
  "regulatory_changes": [...],
  "predictions": {...},
  "governance_rules": [...],
  "timestamp": "2025-10-14T..."
}

2. Priority Engine

Purpose: Assess urgency and impact to determine priority level

Priority Levels:

  • CRITICAL (score ≥ 80): Immediate action required
  • HIGH (score 60-79): High priority, respond quickly
  • NORMAL (score 30-59): Standard priority
  • LOW (score < 30): Can wait

Factors Considered:

  • Impact on critical services
  • Number of affected users/processes
  • Time sensitivity (deadlines, SLAs)
  • Risk of cascade failures
  • Compliance/regulatory requirements
  • Current system load

3. Strategy Selector

Purpose: Select best action strategy from memory or generate new one

Selection Process:

graph LR A[Receive Context + Priority] --> B{Query Memory} B -->|Found| C[Retrieve Similar Cases] B -->|Not Found| D[Generate New Strategy] C --> E[Score Strategies] D --> E E --> F[Rank by Confidence] F --> G[Return Top 3 Strategies] style A fill:#e0f2fe style G fill:#dcfce7

Strategy Confidence Mapping:

  • ≥ 0.9: Auto-resolve or delegate
  • 0.7-0.89: Delegate to specialist
  • < 0.7: Escalate to human

Strategy Metadata:

{
  "action": "Restart workflow X",
  "rationale": "Similar case succeeded",
  "confidence": 0.92,
  "learned_from": ["case_123", "case_456"],
  "requires_expert": false,
  "domain": "workflow_management"
}

4. Safety Monitor

Purpose: Validate decisions against safety rules before execution

Constitution Enforcer

Check against core rules: never modify user data without permission, never delete audit trails

Loop Detector

Prevent circular decision patterns and infinite loops

Hallucination Detector

Detect unrealistic or impossible actions

Control Monitor

Ensure human oversight for critical decisions

Safety Check Result

If safety check fails → decision is automatically converted to ESCALATE_HUMAN with safety concerns listed

5. Delegation Manager

Purpose: Route decisions to appropriate execution path or AI specialists

Action Types:

AUTO_RESOLVE

  • Call platform services directly
  • Automatic retry with exponential backoff
  • Parse action from strategy metadata
  • Route to: BIA, Risk, Planning, Compliance services

DELEGATE

  • Send to AI specialists (Expertise Center)
  • Publish delegation event via EventBus
  • Track delegation status
  • Handle async responses

ESCALATE_HUMAN

  • Create incident ticket
  • Send notifications (email, Slack, PagerDuty)
  • Log escalation for tracking
  • Require manual intervention

EMERGENCY_STOP

  • Halt all workflows
  • Publish critical event
  • Trigger incident response
  • Send emergency notifications
