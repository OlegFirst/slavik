MIO Manager

Intelligent Monitoring & Observability Manager

Port 8046 | Platform Eyes | Observatory Pattern | Self-Healing

The Platform Eyes

MIO Manager is the Observatory of the platform - constantly watching, learning, and maintaining health. It doesn't command, it observes and reports. It doesn't decide, it informs decision-makers.

Observatory Pattern

Continuous observation without intervention. Publishes findings to EventBus for choreography-based responses.

Smart Scheduling

Multi-cycle monitoring: continuous (30s), hourly, daily (3am), weekly (Monday), monthly. Focused, deep analysis.

Self-Healing Integration

Integrates with DevOps Agent, AI Event Manager, Predictive Service for proactive problem detection and resolution.

Core Responsibilities

  • Metrics Coverage: Ensure all services export Prometheus metrics
  • Health Monitoring: Check service health every 60 seconds
  • Deep Analysis: Daily (3am) deep performance analysis
  • Focus Analysis: Weekly (Monday) component-by-component review
  • Automation Setup: Configure Prometheus scrape jobs and Grafana dashboards
  • Critical Escalation: Detect failures and publish to EventBus
  • Report Generation: Daily (6am), weekly (8am), monthly reports to Workflow Intelligence
  • ML Model Retraining: Weekly (Sunday) predictive model updates

Key Architectural Principles

Observatory (Not Commander)

  • Observe: Continuously watch all services
  • Analyze: Use AI to understand patterns
  • Publish: Send findings to EventBus
  • Never Command: Other services react autonomously

Choreography (Not Orchestration)

  • Event-Driven: Publish observations as events
  • Decoupled: Services subscribe to relevant events
  • Autonomous: Each service decides its own actions
  • Scalable: No single point of failure

How MIO observes a problem and triggers choreographed responses

Scenario: Critical Service Failure

1. Detection (Health Check Cycle - 60s)

{
  "service": "workflow_intelligence",

  "detected_at": "2025-10-14T03:42:15Z"

2. MIO Observation (Observatory Pattern)

// MIO publishes observation to EventBus
await eventbus.publish(
  'platform.mio.critical_service_failure_observed',
  {
    observation: 'Workflow Intelligence unavailable',
    severity: 'critical',
    services: [{service: 'workflow_intelligence', status: 'down'}],
    detected_at: '2025-10-14T03:42:15Z',
    recommendations: [
      {
        recommendation: 'Investigate service failures immediately',
        priority: 'critical'
      }
    ]
  },
  priority: 'critical'
)

3. Choreographed Responses (Autonomous)

DevOps Agent Restarts container, checks logs, exports metrics
AI Event Manager Learns failure pattern, suggests prevention
Policy Engine Checks if escalation policy triggered
Notification Service Alerts on-call engineer via Slack/PagerDuty

4. MIO Continues Observing

MIO keeps monitoring health checks. Once service recovers, publishes platform.mio.service_recovered event. Collects data for daily report (6am).

Key Learnings from Example

What MIO Does

  • ✓ Detects failure in 60 seconds
  • ✓ Publishes observation to EventBus
  • ✓ Continues monitoring for recovery
  • ✓ Includes findings in daily report

What MIO Does NOT Do

  • ✗ Does not restart services (DevOps Agent does)
  • ✗ Does not decide who to notify (Policy Engine does)
  • ✗ Does not learn patterns (AI Event Manager does)
  • ✗ Does not coordinate actions (Coordination Center does)

EventBus Integration (integrations/eventbus_client.py)

Publishes observations to EventBus for choreography-based responses 

class EventBusClient:
    async def publish_problem_detected(
        self,
        problem: Dict[str, Any],
        severity: str,
        source: str = 'mio-manager'
    ) -> bool:
        return await self._publish_event(
            event_type='mio.problem_detected',
            data={
                'problem': problem,
                'severity': severity,
                'detected_at': datetime.utcnow().isoformat()
            },
            source=source,
            priority=self._severity_to_priority(severity)
        )

    # Subscribe to events from other services
    async def subscribe_to_problems(self, callback)
    async def subscribe_to_tasks(self, callback)
    async def subscribe_to_directives(self, callback)

Metrics Coverage Observer (monitoring/)

Phase 2.1 "MIO EYES" - observes metrics coverage without commanding 

class MetricsCoverageObserver:
    async def observe_coverage(self):
        # Get all registered services
        services = await self.get_services()

        # Check which have Prometheus metrics
        with_metrics = await self.check_prometheus_targets()

        # Calculate coverage
        coverage_percentage =
            (len(with_metrics) / len(services)) * 100

        # Create observation
        observation = Observation(
            coverage_percentage=coverage_percentage,
            missing_services=[...],
            detected_at=datetime.utcnow()
        )

        # Publish to EventBus (NOT command!)
        await self.publish_observation(observation)

        return observation

Automation Toolkit Manager (integrations/)

Automates monitoring setup: Prometheus configs, Grafana dashboards 

class AutomationToolkitManager:
    async def setup_monitoring(self):
        # 1. Discover all services
        services = await self.discover_services()

        # 2. Generate Prometheus scrape jobs
        prometheus_config =
            self.generate_prometheus_config(services)
        await self.apply_prometheus_config(prometheus_config)

        # 3. Create Grafana dashboards
        for service in services:
            dashboard = self.generate_grafana_dashboard(service)
            await self.create_grafana_dashboard(dashboard)

        # 4. Calculate coverage
        coverage = len([s for s in services if s.has_metrics])
        coverage_percentage = (coverage / len(services)) * 100

        return {
            'prometheus_config': prometheus_config,
            'grafana_dashboard': len(services),
            'coverage_percentage': coverage_percentage
        }
