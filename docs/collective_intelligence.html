What is a Collective Agent?

A temporary AI created from multiple organizations' experiences to help someone stuck on the same problem

Real Conversation Example

User (Hospital A - Stuck):

"We've been struggling with supply chain dependencies in BIA for 2 weeks. How do we map Tier 2 suppliers when our Tier 1 suppliers won't share that information?"

Platform:

"I've detected you're stuck on supply chain mapping. Good news! 5 healthcare organizations in our network successfully solved this exact challenge. I've created a Collective Agent from their combined experience. Would you like to chat with it?"

Collective Agent (Representing B, C, D, E, F):

"Organizations that solved supply chain mapping typically started with their Tier 1 suppliers and sent structured questionnaires. 3 out of 5 used a simple template asking: 'Which of YOUR suppliers would impact us if disrupted?' The common pattern was to set boundaries—focus on top 80% of spend. 2 organizations took a different approach and conducted workshops with Tier 1 suppliers, which worked well but required more time. The challenge everyone faced was incomplete data. They addressed this by iterating: start with what you have, flag gaps, and refine over time."

User:

"This is amazing! Can you tell me which hospitals these are so I can contact them?"

Collective Agent:

"That information is anonymous to protect confidentiality. However, their collective wisdom is now yours to use. The approaches I described came from healthcare organizations similar to yours (200-500 bed hospitals). Is there a specific aspect of supply chain mapping you'd like to explore further?"

Result: User A got unstuck using wisdom from 5 organizations. Organizations B, C, D, E, F remain completely anonymous. Everyone wins!

3-Layer Privacy Architecture

Multiple layers of anonymization ensure complete privacy protection

Layer 1: Organization Anonymization

Remove all identifiers:

BEFORE:

{
  "org_name": "Memorial Hospital Seattle",
  "author": "John Smith",
  "processes": [...]
}

AFTER:

{
  "org_type": "hospital_200-500_beds",
  "region": "pacific_northwest",
  "processes": [...]
}

Layer 2: Aggregation

Require ≥5 organizations minimum:

Individual cases combined:

{
  "pattern": "emergency_dept_priority",
  "frequency": "4_out_of_5",
  "confidence": 0.8
}

Prevents "this is probably Hospital X" deduction

Layer 3: AI Synthesis

Natural language collective response:

Agent says:

"Organizations that completed BIA typically prioritized emergency departments first (4 out of 5 cases)."

No way to trace back to source organizations

5 Privacy Rules

Rule 1: Minimum Threshold

Need ≥5 organizations to create collective agent. Prevents "this is probably Hospital X" deduction.

Rule 2: No Outlier Highlighting

Never say "one organization did Y differently." Prevents deduction by elimination.

Rule 3: Aggregate Statistics Only

"4 out of 5" not "80% including Hospital X." Mean, median, quartiles only.

Rule 4: No Time Correlation

Can't track specific org over time. No "Organization A's journey month by month."

Rule 5: Geographic Generalization

"Pacific Northwest" not "Seattle." Regions, not cities.

Result: 100% Privacy

Mathematically impossible to identify source organizations through Collective Agent responses.

Collective Agent Lifecycle: Creation to Expiration

Phase 1: Creation

When user stuck (≥7 days no progress)

  1. Stuck detector identifies problem type
  2. Search case library for solvers (min 5 orgs)
  3. Extract anonymized approaches
  4. Create collective agent with synthesized prompt
  5. Set expiration: 7 days from creation

Phase 2: Chat

User interacts with agent

  • User asks questions about their problem
  • Agent responds with synthesized wisdom
  • Always speaks as "organizations that..."
  • Never reveals source identities
  • Acknowledges gaps: "This wasn't covered"
  • Conversation logged (anonymously)

Phase 3: Expiration

After 7 days (automatic cleanup)

  • Archive conversation (anonymized)
  • Delete collective agent

  • Learnings added to case library

Why expire? Prevents users from reverse-engineering source orgs through multiple conversations over time.

Stuck Organization Detection: When to Offer Help

AI automatically detects when organizations need collective assistance

5 Detection Signals

1. No Progress (7+ days)

Signal: Workflow stage unchanged for >7 days
Weight: +3 stuck score
Example: BIA data collection stuck at 20% for 10 days

2. Validation Failures (5+)

Signal: Multiple AI validation rejections
Weight: +2 stuck score
Example: BIA document rejected 6 times for completeness

3. Low AI Confidence (<0.6)

Signal: AI assistance confidence scores dropping
Weight: +2 stuck score
Example: AI can't provide good recommendations (avg 0.45)

4. Repeated Questions (3+)

Signal: User asks same question multiple times
Weight: +1 stuck score
Example: "How do I identify dependencies?" asked 4 times

5. Document Loops (5+ revisits)

Signal: Same document page viewed repeatedly
Weight: +1 stuck score
Example: ISO 22301 clause 8.2 viewed 7 times in 2 days

Stuck Score Calculation

stuck_score = 0

# Signal 1: No progress
if days_no_progress > 7:
    stuck_score += 3  # Critical
elif days_no_progress > 3:
    stuck_score += 1  # Warning

# Signal 2: Validation failures
if validation_failures > 5:
    stuck_score += 2

# Signal 3: Low confidence
if avg_confidence < 0.6:
    stuck_score += 2

# Signal 4: Repeated questions
if repeated_questions > 3:
    stuck_score += 1

# Signal 5: Document loops
if document_revisits > 5:
    stuck_score += 1

# Decision
if stuck_score >= 4:
    offer_collective_help()  # Create agent
elif stuck_score >= 2:
    send_proactive_tips()  # Soft help
else:
    continue_monitoring()  # Normal
