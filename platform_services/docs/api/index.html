🚀 Quick Start

Authentication

All API endpoints require JWT Bearer token authentication:

curl -H "Authorization: Bearer YOUR_JWT_TOKEN" \
     http://localhost:8012/api/bia/processes

Development Mode

For development/testing, use the X-Dev-User header:

curl -H "X-Dev-User: {\"sub\":\"user-123\",\"tenant_id\":\"tenant-abc\",\"permissions\":[\"BIA_VIEW\"]}" \
     http://localhost:8012/api/bia/processes

🔐 Authentication & Authorization

All endpoints require authentication! Use JWT Bearer tokens in production or X-Dev-User header for development.

JWT Token Structure

{
  "sub": "user-123",           // User ID
  "tenant_id": "tenant-abc",   // Tenant ID (for multi-tenancy)
  "permissions": [             // RBAC permissions
    "BIA_VIEW",
    "BIA_CREATE",
    "COMPLIANCE_VIEW"
  ],
  "exp": 1735689600           // Token expiration
}

RBAC Permissions by Service

  • BIA Service: BIA_VIEW, BIA_CREATE, BIA_UPDATE, BIA_DELETE, BIA_COMPLETE, BIA_AI_SUGGEST
  • Compliance Service: COMPLIANCE_VIEW, COMPLIANCE_EDIT, AUDIT_MANAGE, NC_MANAGE
  • Planning Service: STRATEGY_VIEW, STRATEGY_CREATE, STRATEGY_APPROVE
  • Plans Service: PLAN_VIEW, PLAN_CREATE, PLAN_APPROVE, PLAN_ACTIVATE

🔗 Integration & Workflows

Cross-Service Workflows

  • BIA → Strategy: Completed BIA triggers strategy creation event
  • Strategy → Plan: Approved strategy triggers plan creation
  • Audit → Gap → NC → CAPA: Full compliance improvement cycle
  • Plan Activation: Real incident tracking and lessons learned

Event-Driven Architecture

Services communicate via EventBus (RabbitMQ on port 8001):

  • bia.analysis.completed
  • planning.strategy.approved
  • compliance.audit.completed
  • plans.activation.started
