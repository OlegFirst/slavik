# Стандарты данных для Digital Twin System

## 📊 Уровни полноты данных для эффективной работы

### 🔴 МИНИМАЛЬНЫЙ набор данных (Базовая функциональность)
**Эффективность системы: 30-40%**

#### Организационные данные:
```json
{
  "organization": {
    "name": "string",              // Название организации
    "type": "non-profit",           // Тип (обязательно)
    "size": 10,                     // Количество сотрудников (минимум 1)
    "annual_budget": 50000          // Годовой бюджет (минимум $10,000)
  }
}
```

#### Минимальные требования:
- **Сотрудники:** минимум 1 человек
- **Бюджет:** минимум $10,000/год
- **Данные:** обновление раз в месяц
- **История:** минимум 3 месяца данных

#### Возможности при минимальном наборе:
- ❌ Точные прогнозы (погрешность >40%)
- ❌ Сложные симуляции
- ✅ Базовая визуализация структуры
- ✅ Простые метрики здоровья
- ⚠️ Ограниченные рекомендации

## ⚠️ Критические пороги

### Ниже минимума система НЕ РАБОТАЕТ если:
- ❌ Менее 1 сотрудника
- ❌ Бюджет менее $10,000
- ❌ Нет данных за последние 3 месяца
- ❌ Отсутствует базовая информация об организации
- ❌ Нет финансовых данных вообще

### Система работает НЕЭФФЕКТИВНО если:
- ⚠️ Данные обновляются реже раза в месяц
- ⚠️ История менее 6 месяцев
- ⚠️ Менее 3 KPI метрик
- ⚠️ Нет структуры отделов
- ⚠️ Отсутствуют данные о программах

## 📊 Формулы расчета эффективности

### Коэффициент полноты данных (DCC):
```
DCC = (Actual_Data_Points / Required_Data_Points) × 100%

Где:
- Минимум: DCC < 40% - система неэффективна
- Средний: DCC 40-75% - базовая эффективность
- Полный: DCC > 75% - максимальная эффективность
```

### ROI от Digital Twin:
```
ROI = (Savings + Revenue_Increase - System_Cost) / System_Cost × 100%

Ожидаемый ROI:
- Минимум данных: 20-50%
- Средний уровень: 150-250%
- Полный набор: 300-500%
```
