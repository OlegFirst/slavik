# BCM Core - Базовый модуль системы

## Обзор модуля

**Назначение**: Фундаментальный модуль, предоставляющий базовую функциональность и абстрактные модели для всей BCM платформы.

**Расположение**: `core/odoo-18.0/addons/bcm_core/`

## Ключевые компоненты

### Модели данных

#### 1. BCMBaseModel (bcm.base.model)
**Файл**: `models/bcm_base_model.py:15`

**Назначение**: Абстрактная базовая модель для всех BCM объектов

**Поля**:
- `client_id` (Many2one) - Связь с клиентом для мульти-тенантности
- `is_active` (Boolean) - Статус активности
- `created_date` (Datetime) - Дата создания
- `modified_date` (Datetime) - Дата последнего изменения
- `created_by` (Many2one) - Пользователь-создатель
- `modified_by` (Many2one) - Пользователь, последний раз изменявший
- `version` (Integer) - Версия записи для контроля изменений

**Ключевые методы**:
```python
def create(self, vals_list):
    """Переопределение создания записей с автоматическим заполнением метаданных"""
    
def write(self, vals):
    """Переопределение обновления записей с версионированием"""
    
def archive_record(self):
    """Архивирование записи вместо удаления"""
    
def get_client_context(self):
    """Получение контекста клиента для фильтрации данных"""
```

#### 2. BCMTagModel (bcm.tag.model)
**Файл**: `models/bcm_tag_model.py:12`

**Назначение**: Модель для системы тегов и категоризации

**Поля**:
- `name` (Char) - Название тега
- `color` (Integer) - Цвет тега в интерфейе
- `category` (Selection) - Категория тега (risk, incident, plan, etc.)
- `description` (Text) - Описание назначения тега

- `bcm_core.group_bcm_admin` - Администраторы BCM

- `bcm_core.group_bcm_viewer` - Просмотр BCM данных

#### 2. Base List View  
**Файл**: `views/bcm_base_views.xml:45`

- Базовый список с фильтрацией по клиентам

- Цветовое кодирование по статусам

### Конфигурация

#### Системные параметры:
- `bcm.core.default_timezone` - Часовой пояс по умолчанию
- `bcm.core.retention_period` - Период хранения архивных данных
- `bcm.core.notification_enabled` - Включение уведомлений

### Интеграция с другими модулями

**Используется в**:
- Все 18 остальных BCM модулей наследуют от базовых моделей
- Система тегов используется во всех модулях для категоризации
- Валидаторы используются для проверки данных

**Интеграционные точки**:
- `bcm_clients` - Мульти-тенантность через client_id
- `bcm_intelligent_base` - AI анализ базовых метрик
- Все модули - Наследование базовой функциональности

### Рабочие процессы (Workflows)

1. **Создание записи BCM объекта**:
   - Валидация входных данных → Установка метаданных → Применение правил безопасности → Создание записи

2. **Обновление записи**:
   - Проверка прав доступа → Версионирование → Обновление метаданных → Уведомления

3. **Архивирование**:
   - Мягкое удаление → Сохранение в архив → Логирование действия
