================================================================================
                         DATA FLOW EXAMPLE: Risk Analysis
================================================================================

1. SERVICE STARTUP
   ├─ Risk Service initializes
   ├─ Calls init_platform() from infrastructure
   ├─ Platform initializes:
   │  ├─ EventBus (+ Intelligent Router)
   │  ├─ Saga Engine
   │  ├─ CQRS handlers
   │  └─ Database connection
   └─ Risk Service subscribes to events

2. USER CREATES RISK
   ├─ REST API: POST /risks
   ├─ Risk Service receives request
   ├─ Validates input (using security module)
   ├─ Creates Risk Command (CQRS)
   ├─ Command Handler persists to database
   │  ├─ PostgreSQL: Save risk record
   │  ├─ Redis: Cache risk data
   │  └─ Publish RiskCreatedEvent
   └─ Return response to client

3. INTELLIGENT ROUTING
   ├─ RiskCreatedEvent published to EventBus
   ├─ Intelligent Router analyzes event:
   │  ├─ Semantic analysis: "This is a risk creation event"
   │  ├─ Load analysis: "Risk Service load = 60%"
   │  ├─ Capability matching: "Compliance Service can validate"
   │  └─ AI suggestions: "Route to Expert AI for impact assessment"
   └─ Determine target subscribers

4. EVENT DISTRIBUTION
   ├─ Route to Compliance Service
   │  ├─ Handler: validate_risk_compliance()
   │  ├─ Updates database with validation result
   │  ├─ Publishes RiskValidatedEvent
   │  └─ Updates metrics
   ├─ Route to Learning Service
   │  ├─ Handler: learn_from_risk()
   │  ├─ Updates ML models
   │  ├─ Publishes LearningUpdatedEvent
   │  └─ Stores embeddings in Vector DB
   └─ Route to Expertise Center
      ├─ AI analysis: Impact assessment
      ├─ Publishes ImpactAssessmentEvent
      ├─ Updates knowledge base
      └─ Triggers decision consultation

5. METRICS & OBSERVABILITY
   ├─ Prometheus collects metrics:
   │  ├─ event_published_total{type="RiskCreated"}
   │  ├─ event_processing_duration_seconds
   │  ├─ eventbus_subscriber_lag
   │  └─ database_query_duration_seconds
   ├─ Grafana displays dashboards
   ├─ Jaeger traces distributed requests
   ├─ ELK Stack logs all events
   └─ Notifications send alerts if needed

6. POLICY ENFORCEMENT
   ├─ Policy Engine checks policies:
   │  ├─ Policy: "All risks >= HIGH must be escalated"
   │  ├─ This risk = HIGH
   │  ├─ Trigger escalation
   │  └─ Notify decision center
   └─ Decision Center creates decision record
