│ PRODUCTION USAGE                                                             │
└──────────────────────────────────────────────────────────────────────────────┘

  1. Configure environment:
     export JWT_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
     export JWT_ALGORITHM="RS256"
     export JWT_AUDIENCE="bcm-platform"  # Optional

  2. Make requests:
     curl -X GET http://localhost:8023/api/plans/plans \
       -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIs..."

┌──────────────────────────────────────────────────────────────────────────────┐
│ DEVELOPMENT USAGE                                                            │
└──────────────────────────────────────────────────────────────────────────────┘

     export JWT_PUBLIC_KEY=""

  2. Use development header:
     curl -X GET http://localhost:8023/api/plans/plans \
       -H "X-Dev-User: user_id:tenant_id:email"

     Example:
     curl -X GET http://localhost:8023/api/plans/plans \
       -H "X-Dev-User: dev_user:dev_tenant:dev@test.com"

┌──────────────────────────────────────────────────────────────────────────────┐
│ TENANT ISOLATION                                                             │
└──────────────────────────────────────────────────────────────────────────────┘

  How it works:
    1. tenant_id extracted from JWT token (NOT from request)
    2. All queries filtered by current_user.tenant_id
    3. Cross-tenant access returns 403 Forbidden
    4. Superadmins (is_superadmin=true) can access all tenants

  Security guarantee:
    ✅ Users can ONLY access data within their tenant
    ✅ No way to specify tenant_id in request
    ✅ Token claims are the single source of truth
