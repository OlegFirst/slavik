# БЛОК 1: СУТЬ BCM ТА ISO 22301

## 1.1 Що таке Business Continuity Management?

### Визначення

**Business Continuity Management (BCM)** — це систематичний підхід до управління організацією, який забезпечує:
- Продовження критичних операцій під час кризи
- Швидке відновлення після інциденту
- Мінімізацію збитків та захист репутації
- Захист життя та безпеки людей

**ISO 22301** — міжнародний стандарт, який визначає вимоги до системи управління неперервністю бізнесу (BCMS - Business Continuity Management System).

### Ключова ідея

ISO 22301 відповідає на питання:  
**"Як гарантувати, що організація виживе при будь-якій кризі?"**

Це не про уникнення проблем — це про **ГОТОВНІСТЬ** та **СТІЙКІСТЬ**.

## 1.2 Проблеми, які вирішує BCM

### Без BCM (Типові проблеми):

**СЦЕНАРІЙ: Кібератака на організацію**

```
День 1, 03:00 - Ransomware зашифрував сервери
                ↓
       Паніка: "Що робити?!"
                ↓
       Немає плану дій
                ↓
День 1, 09:00 - Операції зупинені
       Клієнти не обслуговуються
       Втрата даних
                ↓
День 7 - Репутаційні втрати
       Регуляторні штрафи
       Клієнти йдуть до конкурентів
                ↓
Місяць 1 - Фінансова криза
       Можлива ліквідація
```

**Статистика:**
- 60% організацій без плану не виживають після major disaster
- Середній час простою: 14 днів
- Середні збитки: €2M-10M
- 93% малих організацій закриваються протягом року після катастрофи

### З BCM (Контрольована ситуація):

**СЦЕНАРІЙ: Та сама кібератака**

```
День 1, 03:00 - Ransomware зашифрував сервери
                ↓
        03:05 - Автоматична сигналізація
                ↓
        03:10 - Crisis Manager активує BCP
                ↓
        03:15 - Мережа ізольована
                ↓
        04:00 - Перехід на резервні системи
                ↓
День 1, 08:00 - Операції працюють у резервному режимі
       Клієнти обслуговуються
       Відновлення з backup
                ↓
День 1, 14:00 - Системи повністю відновлені
       Дані синхронізовані
                ↓
День 2 - Post-incident review
       Оновлення процедур
       Організація сильніша
```

**Результат:**
- Час простою: 11 годин (замість 14 днів)
- Збитки: €50K (замість €2M+)
- Репутація: покращилася ("надійна організація")
- Клієнти: залишилися (навіть не помітили проблему)

### Основні проблеми, які вирішує BCM:

| Проблема | Як BCM вирішує |
|----------|----------------|
| **Хаос під час кризи** | Чіткі процедури, кожен знає свою роль |
| **Втрата даних** | Регулярні backup, протестовані процедури відновлення |
| **Тривалий простій** | Резервні системи та workaround процедури |
| **Репутаційні збитки** | План комунікацій, швидка реакція |
| **Регуляторні штрафи** | Відповідність вимогам, документовані процеси |
| **Залежність від ключових людей** | Знання в системі, а не в головах |
| **Фінансові втрати** | Мінімізація часу простою = збереження доходу |

## 1.3 Структура стандарту ISO 22301

ISO 22301 побудований на циклі **PDCA (Plan-Do-Check-Act)** — безперервному процесі вдосконалення.

### 10 основних розділів стандарту:

#### Розділ 4: КОНТЕКСТ ОРГАНІЗАЦІЇ
**Мета:** Зрозуміти своє середовище

**Що визначаємо:**
- Хто stakeholders? (клієнти, регулятори, партнери, співробітники)
- Що для них критично важливо?
- Які зовнішні загрози? (стихійні лиха, кібератаки, пандемії, війни)
- Які внутрішні ризики? (обладнання, персонал, процеси)

**Приклад:**
```
Організація: IT-компанія

Stakeholders:
✓ Клієнти B2B (залежать від нашого SaaS)
✓ Співробітники (150 осіб)
✓ Інвестори (очікують ROI)

Зовнішні ризики:
✓ DDoS атаки
✓ Відключення електроенергії
✓ Проблеми з cloud провайдером

Внутрішні ризики:
✓ Ключові розробники (bus factor)
✓ Сервери (single point of failure)
✓ Код без документації
```

---

#### Розділ 5: ЛІДЕРСТВО
**Мета:** Топ-менеджмент ПОВИНЕН бути залученим

**Вимоги:**
- ✅ CEO/Директор підписує BCM Policy
- ✅ Призначає BCM Manager з повноваженнями
- ✅ Виділяє бюджет та ресурси
- ✅ Регулярно (щоквартально) переглядає статус BCM

**Чому це важливо:**
- ❌ Без підтримки керівництва: BCM = формальність (папірець)
- ✅ З підтримкою керівництва: BCM = частина культури організації

---

#### Розділ 6: ПЛАНУВАННЯ ⭐ (КРИТИЧНО)
**Мета:** Визначити ЩО захищати

**Ключовий інструмент: BIA (Business Impact Analysis)**

BIA відповідає на питання:  
*"Якщо ЦЕЙ процес зламається, як ШВИДКО ми помремо?"*

**Метафора:** Організація = людина
- Серце (критичні операції): RTO = 0 хвилин
- Легені (важливі системи): RTO = 30 хвилин  
- Шлунок (допоміжні функції): RTO = 24 години
- Волосся (некритичне): RTO = необмежено

**Приклад BIA:**

```
┌──────────────────────────────────────────────────────────┐
│ Процес           │ RTO     │ Макс.Простій │ Критичність │
├──────────────────────────────────────────────────────────┤
│ Онлайн-продажі   │ 30 хв   │ 4 години     │ КРИТИЧНО    │
│ Обслуговування   │ 2 год   │ 8 годин      │ ВИСОКО      │
│ Email            │ 4 год   │ 1 день       │ СЕРЕДНЬО    │
│ Бухгалтерія      │ 3 дні   │ 1 тиждень    │ НИЗЬКО      │
└──────────────────────────────────────────────────────────┘
```

**RTO (Recovery Time Objective):**  
= Максимальний час простою, який можна допустити

**RPO (Recovery Point Objective):**  
= Скільки даних можемо втратити

**Фінансовий вплив:**
```
Формула: Збиток/год = Втрачений дохід + Штрафи + Репутація

Приклад:
Онлайн-продажі зупинені:
- Втрачений дохід: €10K/год
- Штрафи (SLA): €5K/год
- Репутація: €15K/год
━━━━━━━━━━━━━━━━━━━━━━━
TOTAL: €30K/год × 4 години = €120K збитків

Вивід: Варто інвестувати в резервування!
```

#### Розділ 9: ОЦІНКА ЕФЕКТИВНОСТІ
**Мета:** Перевіряй чи працює план

**Типи тестування:**

**1. Tabletop Exercise (Настільна гра)**
- Час: 2-3 години
- Команда обговорює сценарій за столом
- Знаходить логічні проблеми
- Частота: 2 рази на рік

**2. Simulation Exercise (Симуляція)**
- Час: 4-8 годин
- Притворяємось, що криза реальна
- Тестуємо процедури на практиці
- Клієнти НЕ зачеплені (sandbox)
- Частота: 1 раз на рік

**3. Full Exercise (Повна тренування)**
- Час: Повний день
- РЕАЛЬНО перемикаємось на backup
- Клієнти зачеплені (дуже ризиковано!)
- Частота: Опціонально

**Внутрішній аудит:**
- Хто: Незалежний аудитор (НЕ BCM-менеджер)
- Коли: Мінімум 1 раз на рік
- Що: Перевірка відповідності всім вимогам

**Management Review:**
- Хто: CEO + Crisis Manager
- Коли: Щоквартально
- Що: Статус програми, інциденти, рішення на майбутнє

## 1.4 Чому це критично важливо

### 4 основні причини сертифікації ISO 22301:

#### 1. РЕГУЛЯТОРНІ ВИМОГИ
**Хто вимагає:**
- Банки та страхові (фінансові регулятори)
- Лікарні (міністерства охорони здоров'я)
- Критична інфраструктура (уряд)
- Обробка персональних даних (GDPR + BCM)

**Якщо НЕ сертифікований:**
- ❌ Штрафи €50K-500K+
- ❌ Втрата ліцензії
- ❌ Кримінальна відповідальність (у крайніх випадках)

---

#### 2. ВИМОГИ КЛІЄНТІВ
**B2B клієнти питають:**  
"У вас є ISO 22301?"

**Якщо НІ:**
- ❌ Великі контракти не підписують
- ❌ Enterprise клієнти йдуть до конкурентів
- ❌ Урядові тендери недоступні

**Якщо ТАК:**
- ✅ Конкурентна перевага
- ✅ Доступ до великих клієнтів
- ✅ Вищі ціни (премія за надійність)

---

#### 3. УПРАВЛІННЯ РИЗИКАМИ (ROI)

**Розрахунок економіки:**

```
ІНВЕСТИЦІЯ В BCM:
├─ Сертифікація: €50K (перший рік)
│  З AI платформою: €5K ⚡ (економія 90%)
└─ Підтримка: €10K/рік

ВАРТІСТЬ КРИЗИ БЕЗ ПЛАНУ:
└─ Один major incident: €2M збитків

ВАРТІСТЬ КРИЗИ З ПЛАНОМ:
└─ Той самий incident: €200K збитків

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ЕКОНОМІЯ: €1.8M з ПЕРШОГО інциденту!

Ймовірність major incident: 15-20% на рік
Expected value економія: €270K-360K/рік

ROI: 540-720% у перший рік!
```

---

#### 4. КОНКУРЕНТНА ПЕРЕВАГА

**Маркетинг:**
- ✅ "ISO 22301 Сертифіковані"
- ✅ = "Ми надійні, можете нам довіряти"

**Особливо важливо для:**
- Фінансові послуги (гроші клієнтів)
- Охорона здоров'я (життя людей)
- Cloud/SaaS провайдери (бізнес клієнтів залежить від вас)
- НПО (донори вимагають прозорості та надійності)

**Результат:**
- → Більше клієнтів (довіра)
- → Менше churn (впевненість)
- → Вищі ціни (премія)
- → Кращі інвестори (due diligence)

### Філософія стандарту: RESILIENCE (Стійкість)

ISO 22301 НЕ про "уникнути проблем"  
ISO 22301 про "ВИЖИТИ незважаючи на проблеми"

**Метафора: Дерево під час шторму**

```
Слабке дерево (крихке):
  Шторм → дерево ламається → дерево мертве

Сильне дерево (resilient):
  Шторм → дерево гнеться → шторм минув  
  → дерево випрямилось → коріння глибше
  → дерево СИЛЬНІШЕ ніж до шторму
```

**4 рівні зрілості:**

```
РІВЕНЬ 1: FRAGILE (Крихкий)
  Криза → Організація помирає
  
РІВЕНЬ 2: ROBUST (Міцний)
  Криза → Організація витримує (але страждає)
  
РІВЕНЬ 3: RESILIENT (Стійкий) ← ISO 22301 ЦІЛЬ
  Криза → Швидке відновлення за планом
  
РІВЕНЬ 4: ANTIFRAGILE (Анти-крихкий)
  Криза → Організація стає СИЛЬНІШОЮ
```

### Впровадження ЦГЗ: Комплексна система BCM

**1. Risk Management**

ЦГЗ впровадив систему де ризики всіх структурних підрозділів ідентифікуються, оцінюються й переглядаються регулярно, з урахуванням змін у процесах і зовнішньому середовищі.

```
Визначаються:
├─ Ймовірні події:
│  • Перебої електроенергії (висока ймовірність в Україні)
│  • Відмова обладнання
│  • Кіберзагрози
│  • Логістичні проблеми (війна)
│
├─ Потенційний вплив на процеси
│  • Лабораторна діагностика
│  • Моніторинг епідемій
│  • Звітність
│
└─ Способи реагування та заходи контролю
```

**2. Превентивні заходи**

ЦГЗ створив комплексну систему планів:

**План DRP (Disaster Recovery Plan)**
Встановлює процедури відновлення інформаційних систем після збоїв, щоб мінімізувати час простою та зберегти дані й активи.

**План BCP (Business Continuity Plan)**
Регламентує дії у разі кризових ситуацій, щоб забезпечити виконання бізнес-процесів навіть у мінімально прийнятному режимі.

**План управління кризовими ситуаціями**
Описує процес ескалації, розподіл ролей та завдання із забезпечення безпеки персоналу, активів і репутації.

**План кризових комунікацій**
Забезпечує оперативну, скоординовану комунікацію з внутрішніми та зовнішніми сторонами, мінімізує ризик дезінформації та визначає резервні канали зв'язку.

**3. Governance: Комітет з управління кризовими ситуаціями**

Комітет відповідає за ухвалення рішень щодо активації планів, розподіл ресурсів і координацію команд реагування.

### Результати впровадження в ЦГЗ

Практика ЦГЗ показує, що ефективність лабораторної діяльності значною мірою залежить від системного підходу до управління ризиками.

```
ДОСЯГНЕННЯ:

✅ Стійкість до енергокризи
   - Робота без перерв навіть під час масових відключень
   - Генератори + UPS забезпечують безперервність

✅ Готовність до кібератак
   - DRP план відпрацьований
   - Backup offline (захищений)
   - Регулярні тести відновлення

✅ Пандемійна готовність
   - BCP для перевантаження системи
   - Масштабування capacity
   - Комунікаційні протоколи

✅ Військова стійкість
   - Робота в умовах війни
   - Евакуаційні плани
   - Резервні локації
```

Інтегровані плани та діяльність Комітету з управління кризовими ситуаціями дозволяють Центру громадського здоров'я зберігати стійкість до криз і виконувати головну функцію: захист здоров'я населення України навіть у надзвичайних умовах.

### Висновки для НПО

**Ключові lessons для НПО BCM:**

```
✅ ОБОВ'ЯЗКОВЕ для виживання НПО:

1. EMERGENCY FUND (6 місяців)
   Більшість НПО живуть "місяць-в-місяць"
   Emergency fund = life insurance

2. DONOR DIVERSIFICATION
   Правило 25%: Жоден донор >25% бюджету
   Краще 10 малих донорів ніж 1 великий

3. MULTIPLE REVENUE STREAMS
   ├─ Institutional grants (foundations, governments)
   ├─ Individual donors (recurring giving programs)
   ├─ Earned income (consulting, training, research)
   └─ Corporate partnerships (CSR programs)

4. TRANSPARENT COMMUNICATION
   Криза? Бути відвертими з donors та stakeholders
   Прозорість → довіра → підтримка

5. MISSION-DRIVEN CUTS
   Якщо треба різати: Зберегти core mission
   Operations можна урізати, mission - ні

6. PARTNERSHIPS
   Інші НПО = не конкуренти, а партнери
   Можуть перейняти програми якщо ви закриєтесь

7. VOLUNTEERS ≠ FREE
   Волонтери потребують координації, навчання
   Включити volunteer management в BCM

8. DATA PROTECTION CRITICAL
   Beneficiary data = highly sensitive
   GDPR breach → втрата довіри = смерть НПО
```

# ЗАКЛЮЧЕННЯ

## Ключові висновки

### 1. BCM - це не опція, це необхідність

```
ФАКТИ:
├─ 60% організацій БЕЗ плану не виживають після major disaster
├─ 93% малих організацій закриваються протягом року після катастрофи
├─ Середні збитки БЕЗ плану: €2M-10M
└─ Середні збитки З планом: €50K-200K (40-200x менше!)

ВИВІД: Питання не "чи станеться криза", а "коли станеться"
```

### 2. ISO 22301 = Перевірена система

```
ISO 22301 надає:
✅ Структуру (10 clauses - всі аспекти покриті)
✅ Best practices (перевірені роками)
✅ Міжнародне визнання (credibility)
✅ Continuous improvement (PDCA cycle)
✅ Certification (proof для клієнтів/регуляторів)
```

### 3. NASH 4.0 = Революція в BCM

```
Традиційний підхід → NASH 4.0:
├─ 12-24 місяці → 3-6 місяців (4-8x швидше)
├─ €100K-180K → €12K-17K (85-90% дешевше)
├─ 500-800 годин роботи → 50-80 годин (AI робить 95%)
├─ Знання у консультанта → Знання в системі (завжди доступні)
├─ Статична документація → Live система (нагадування, updates)
├─ Немає підтримки в кризі → Real-time AI assistant
└─ Локальні lessons → Federated learning (347+ кейсів)
```

### 4. ROI = Незаперечний

```
ПРИКЛАД: Типова IT компанія (150 осіб)

Інвестиція: €19,200 (NASH 4.0)
Вигода рік 1:
├─ Економія vs традиційний: €172,800
├─ Запобігання збиткам: €135,000 (expected value)
└─ TOTAL: €307,800

ROI: 1,603% (окупність <1 місяця!)

Кожен рік далі: €135K+ економія від запобігання crisis
```

### 5. Кожна галузь має специфіку, але принципи однакові

```
UNIVERSAL PRINCIPLES:
1. ЗНАЙ свої ризики (BIA, Risk Assessment)
2. МАЙ план (BCP для кожного critical process)
3. ТРЕНУЙСЯ (Exercises щороку мінімум)
4. ПОКРАЩУЙ (PDCA cycle, lessons learned)

INDUSTRY-SPECIFIC:
├─ Healthcare: RTO = хвилини, життя людей, 24/7
├─ NGO: Donor dependency, limited resources, mission first
├─ Finance: Regulatory, data security, instant transactions
├─ Manufacturing: Supply chain, machinery, just-in-time
└─ SaaS/Tech: Uptime SLAs, data backups, cyber resilience

AI Platform адаптується під кожну специфіку!
```
